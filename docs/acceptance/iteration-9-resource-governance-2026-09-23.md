# 迭代九资源治理验收记录（2026-09-23）

## 范围

本轮实现 P03/P04 的生产路径：整机 CPU 持续阈值触发安全暂停与自动恢复，系统内存阈值阻止新任务启动并显示等待原因。状态语义和恢复边界以 [ADR-0017](../adr/0017-resource-aware-task-governance.md) 为准。

本轮不包含 P01/P02/P05/P06 的目标设备长时性能与强退验收，也不调整本地单工作器并发数。

## 实现结果

- 新增独立资源阈值状态机：CPU `>50%` 持续 10 秒触发保护，`<30%` 持续 10 秒恢复；等于阈值不触发，短时尖峰会复位计时。
- 工作器增加并行资源监控循环，在文件哈希、解析、OCR 与财务任务运行期间继续采样整机状态。
- CPU 保护只在任务安全点落为暂停，并同时阻止领取新任务；恢复时只处理资源暂停，不恢复用户暂停。
- 内存 `>70%` 立即阻止领取新任务，排队任务持久化显示等待原因；回落到 70% 或以下后恢复正常排队。
- 项目迁移 v15 持久化暂停原因；历史暂停按用户暂停回填，重启时资源暂停重新排队评估、用户暂停保持不变。
- 自动动作写入项目审计事件；前端以文字和警示图标显示自动恢复条件，不用颜色单独传达状态，也不提供无效的手动继续按钮。

## 自动化验证

- 资源状态机专项覆盖严格阈值、持续窗口、CPU 尖峰复位和内存即时门禁。
- 工作器专项覆盖内存等待原因、准入恢复、CPU 安全点、排队门禁、自动恢复、用户暂停隔离、审计内容和重启恢复。
- API 专项覆盖资源暂停拒绝手动恢复，以及用户暂停原因的写入与清除。
- 前端专项覆盖资源暂停只读提示、取消入口和用户暂停的手动继续入口。
- 完整质量门禁通过：前端 lint、30 项组件测试、生产构建、后端 Ruff 和 102 项后端测试全部通过。
- 首次浏览器验收使用真实整机采样；当时内存为 73.4%，P04 正确阻止 5 条依赖后台任务的桌面场景，并在真实界面显示等待原因。其余 4 项通过、7 项按桌面/移动条件跳过。
- 随后使用未进入提交的确定性资源采样夹具隔离主机压力，完整 Playwright 回归为 9 项通过、7 项按条件跳过；PDF 导入、扫描页、财务数据、风险、Excel/Word/PDF 输出和设置链路均通过。

## 结论与后续

P03/P04 已进入真实工作器、项目数据库和任务界面，确定性自动化路径通过。发布前仍需在目标 Windows 设备上运行真实 CPU/内存压力测试，记录 1 秒采样序列、10 秒边界、任务安全点延迟、前台交互响应和恢复后的任务完整性。
