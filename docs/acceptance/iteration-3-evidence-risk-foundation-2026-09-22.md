# 迭代三证据与风险版本基础验收（2026-09-22）

## 范围

本轮建立人工证据选择、风险卡、状态流转和不可覆盖版本的首个纵向闭环。只使用合成 PDF 与 Fake Provider，不连接真实模型，不执行未确认的财务规则。

关联需求：PRD-RET-001 至 004、PRD-RISK-003 至 005、F06、F09、F10。

## 已实现

- Project Schema 版本 2：新增 `risk_items`、`risk_evidence` 和 `risk_versions`，既有项目库在服务启动时自动升级。
- 文档搜索返回页码、文本块、解析方式、解析版本和命中附近的最小上下文。
- 用户可把命中片段标为支持证据或反证，并在处置面板创建人工风险草稿。
- 服务端重新读取原文并校验证据片段；未知页块、被篡改片段和方向冲突均拒绝入库。
- 风险卡包含编号、类型、待评估等级、人工草稿规则版本、证据链、不确定性、人工意见、模型实际路由和版本号。
- 严格执行 PRD 状态路径，状态变更必须填写备注；创建、状态变更和合成解释均生成不可覆盖快照。
- 风险证据可回跳至 PDF 精确页码和原文搜索结果。
- Fake Provider 可生成明确标注的合成解释草稿，外部请求为 0，不执行金额复算或真实模型推理。
- 风险列表刷新失败与资料、任务刷新隔离，避免新增模块影响原有文档工作流。

## 自动化结果

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check.ps1
npm.cmd --prefix frontend run e2e
```

结果：前端 ESLint、9 项 Vitest、生产构建、Ruff 和 36 项 Pytest 全部通过；浏览器验收 6 项通过，4 项按目标视口有意跳过。

新增覆盖：

- 既有项目数据库从 Project Schema v1 自动升级到 v2。
- 风险创建时的服务端原文解析、证据方向、版本 v1 和审计事件。
- 浏览器片段篡改、未知页块、空白备注和同一片段方向冲突的拒绝路径。
- 合法与非法状态流转、人工备注以及历史快照保留。
- Fake Provider 调用审计、不确定性声明、零外部请求和解释版本。
- 从合成 PDF 搜索、选择证据、创建风险、生成解释、流转到已核实 v3，再回跳原文的桌面端闭环。
