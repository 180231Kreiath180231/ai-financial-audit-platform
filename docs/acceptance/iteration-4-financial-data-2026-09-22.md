# 迭代四财务数据与确定性规则验收记录（2026-09-22）

## 范围

本轮实现科目余额表 CSV 的本地导入、不可变数据集、确定性规则、行级证据和待评估风险草稿。数据契约与产品边界以 [ADR-0004](../adr/0004-trial-balance-csv-deterministic-rules.md) 为准。

本轮不接入 Excel、凭证分录、扫描件识别、统计异常模型、自动风险分级或报告导出。所有验收文件均为 synthetic 数据，未使用真实客户资料，也未调用外部模型。

## 环境

- Windows 11 企业版 10.0.22631
- Node.js 24.16.0，npm 11.13.0
- Python 3.12.13，uv 0.11.19
- DuckDB 1.5.5
- 浏览器：Playwright Chromium 与 Codex 应用内浏览器

## 已实现

- 固定 12 列 CSV 契约；支持 UTF-8、UTF-8 BOM 和 GB18030，文件上限 100 MB、数据行上限 50 万。
- 导入前原子校验和预览；结构错误整批拒绝，空金额按零计算但保留原始空值，额外列原样保存但不参与规则。
- 用户确认后进入持久化单工作器；原始 CSV、SHA-256、编码、期间、币种和版本元数据均保留。
- DuckDB 本地分析库与 Decimal 两位小数口径；模型不参与金额复算或规则结论。
- 期初、本期、期末借贷平衡，单科目余额公式和相邻期间净额衔接规则；结果区分通过、失败和无法计算。
- 期间缺口不跨期推断，不把未知结果标记为通过；新增或消失科目仅在非零净额不衔接时形成失败。
- 每个失败规则结果生成一张“待评估 / 待复核”风险草稿，保存输入值、比较基准、计算结果、规则版本和 CSV 行级证据。
- 同一项目内相同 SHA-256 复用已有数据集；同一数据集与规则集版本复用已有运行结果，不重复生成风险。
- 数据集只允许归档，不硬删除；归档后原文件、规则结果、风险、版本和证据链继续可查。

powershell -NoProfile -ExecutionPolicy Bypass -File scripts/check.ps1

结果：

- 前端生产构建：通过。
- 后端 Ruff：通过。
- 后端 Pytest：42 项通过。

浏览器端到端验收：

```powershell
npm.cmd --prefix frontend run e2e
```

结果：7 项适用场景通过，5 项按目标设备条件有意跳过。新增场景覆盖 CSV 预览、确认导入、后台完成、规则计算明细、风险草稿和从风险回跳 CSV 行证据。

后端专项测试同时覆盖：

- 有效导入与规则/风险证据闭环。
- 相同 SHA-256 数据集复用。
- 非法结构原子拒绝。
- 期间缺口返回无法计算。
- 归档后结果与证据保留。
- 规则计算后收到取消请求时清理尚未提交的 DuckDB 数据，避免半成品数据集。

- 深色 1440×900、浅色 940×800、手机竖屏 390×844、手机横屏 844×390 均完成实机渲染检查。
- 四种视口均无页面级横向溢出；宽表只在自身容器内滚动。

## 验收结论

迭代四首版范围通过。本轮形成了从严格 CSV 输入、确定性本地计算、不可变版本到待评估风险和行级回溯的完整纵向切片；自动化与浏览器验收均未发现阻断提交的问题。

## 尚未完成

- Excel 工作簿、凭证级数据和多实体/多币种合并分析未纳入首版。
- 当前规则只覆盖已确认的余额表算术与跨期衔接，不包含 MAD、Z-score 或行业阈值等统计异常检测。
- 风险等级继续保持“待评估”，需要人工复核；系统不会自动给出高、中、低等级。
- 真实外部模型解释、扫描件视觉解析和报告导出仍待后续迭代。
