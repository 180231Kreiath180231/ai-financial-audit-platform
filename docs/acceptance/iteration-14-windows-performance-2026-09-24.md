# 迭代十四 Windows 实机性能验收记录（2026-09-24）

## 范围与结论

本轮在一台真实 Windows 11 设备上执行 P01 至 P06 的受控实测，并复用完整自动化门禁复核 P07。
所有负载均为运行时生成的 synthetic 原生 PDF，严格离线，外部请求为 0。

P01、P02、P03、P04、P06 在本机实测通过；P05 的批量任务级强退恢复通过。由于本机为
32GB 内存、12 核 16 线程设备，高于 PRD 默认的 16GB 轻薄本规格，结果不能替代最终目标设备签收。
P05 的外部 OCR 页级检查点仍只有离线自动化覆盖，没有获批真实服务商条件，因此发布门禁仍保持部分闭合。

## 设备与工具

- 操作系统：Windows 11 企业版 10.0.22631。
- CPU：13th Gen Intel Core i5-13500H，12 核、16 逻辑处理器。
- 内存：31.53GB。
- 磁盘：SSD 所在卷测试前可用约 65.38GB。
- 电源计划：平衡。
- Python 3.12.13，uv 0.11.19。
- Node.js 24.16.0，npm 11.13.0。
- 采样：`psutil`，1 秒间隔。应用 CPU 为后端或前后端进程树 CPU 之和除以 16 个逻辑处理器，
  即按整机百分比口径归一化。

## 测量方法与结果

| 编号 | 场景 | 原始结果 | 判定 |
|---|---|---|---|
| P01 | 独立临时数据目录启动 Uvicorn 与 Vite，稳定后连续空闲采样 600 秒 | 应用 CPU 均值 0.06%、峰值 0.96%；前后端进程树内存峰值 500.2MB；整机内存峰值 69.0% | 本机通过 |
| P02 | 单工作器连续处理 14 份、每份 1000 页的合成原生 PDF，共 14000 页，持续 70.52 秒 | 14 项全部完成；应用 CPU 均值 0.13%、峰值 0.68%；后端内存峰值 143.8MB | 本机通过 |
| P03 | 12 个最小 CPU 压力进程同步起跑；工作器同时处理 8 份、每份 1000 页的合成 PDF | CPU 超过 50% 后 10.94 秒在安全点暂停；低于 30% 后 12.01 秒自动恢复；暂停/恢复审计事件各 1 条；8 项全部完成 | 本机通过 |
| P04 | 内存子进程以 4GB 为分配上限、至少保留 6GB 可用内存，把整机占用推至 72.0% 后再加入任务 | 新任务保持 queued 并显示内存等待原因；释放后记录恢复事件并完成；阻断/恢复审计事件各 1 条 | 本机通过 |
| P05 | 8 份、每份 1000 页的批量任务中，在 2 项完成且 1 项运行时强制终止后端进程树，再以同一数据库重启 | 8 项最终全部完成；强退前完成项的文档 ID 未变化；重复完成事件组为 0；文档数从 2 恢复至 8 | 批量任务级通过；页级外部 OCR 实测未执行 |
| P06 | P02 后台负载期间，每秒读取 PDF、风险列表和全文检索，共各 69 次 | 0 错误；PDF/风险/检索 p95 分别为 72.6/67.9/76.6ms；最大值分别为 2118.7/159.1/163.6ms | 本机通过；PDF 有一次孤立峰值，无持续卡顿 |
| P07 | 本轮未人为耗尽磁盘；完整自动化继续覆盖导入前与分块写入前 10GB 门禁及 `.part` 清理 | 由全量门禁结果复核 | 自动化通过，低磁盘实机演练未重做 |

P06 的 PRD 口径是“常用操作无持续卡顿”，未给出数值阈值。为使本轮可重复，验收脚本采用
零错误、p95 不高于 2 秒、单次最大不高于 5 秒作为本轮操作性判定线；该测量线不修改 PRD。

P03 的 10 秒是资源保护的持续判定窗口，任务随后在下一个安全点落停。最终 10.94 秒暂停和
12.01 秒恢复包含 1 秒采样边界与调度延迟，符合 ADR-0017 的状态语义。

## P03 方法校准记录

原始证据保留了三次非权威尝试，避免只留下成功结果：

1. 第一次压力进程加载了完整项目依赖，创建期间把内存推过 70%，P04 先阻止了新任务；CPU
   窗口到达时没有运行任务可暂停，因此该次 P03 判定无效。
2. 第二次改为最小压力进程，产品暂停/恢复通过，但压力进程未同步起跑。
3. 第三次加入短同步等待，仍因 Windows 端点扫描导致进程创建时间超过等待时间，外部序列只覆盖
   9.08 秒高负载；产品事件通过，但该序列不作为最终证据。
4. 最终将统一起跑时点后移 30 秒，逐秒序列完整覆盖高负载、暂停、低负载、恢复和最终完成。
