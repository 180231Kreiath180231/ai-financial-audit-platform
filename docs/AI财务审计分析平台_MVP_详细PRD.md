> 基准日期：2026-09-19

## 1. 文档目的

本文档定义 AI 财务审计分析平台 MVP 的产品边界、用户流程、功能需求、数据要求、模型接入方式、资源约束、安全要求和验收标准。

本文档是产品、设计、开发、测试和业务验收的共同基准。需求冲突时，以本版本中的产品边界和验收条件为准。

---

## 2. 产品概述

### 2.1 产品定位

平台是一套面向内部审计人员的本地优先 AI 财务审计工作台，用于管理多年财务资料、识别异常、检索证据、形成风险卡片、准备访谈问题并输出审计报告材料。

平台采用“本地确定性计算 + 外部大模型 API”的组合方式：

- 原始文件、项目数据、分析结果和审计轨迹默认保存在用户本机。
- 金额计算、勾稽、趋势、统计指标和风险规则由本地代码执行。
- OCR、视觉理解、非结构化文档归纳和报告草稿优先调用外部模型 API。
- 支持 DeepSeek、GLM、Kimi、通义千问及其他 OpenAI 兼容服务。
- 不在轻薄本上运行本地大模型，不要求 GPU、Docker、WSL 或服务器组件。

### 2.2 产品价值

| 目标 | MVP 提供的价值 |
|---|---|
| 降低资料审阅时间 | 批量导入、增量去重、自动解析、页码检索和风险聚合 |
| 提高异常识别深度 | 跨年度基线、确定性规则、MAD、同比趋势和模型解释 |
| 形成可核查工作成果 | 风险卡片、证据引用、资料清单、访谈问题和固定模板报告 |
| 控制本地资源 | 单工作器、任务降速、CPU/内存阈值和自动暂停恢复 |
| 避免模型锁定 | 服务商、模型、能力、任务路由和备用模型均可配置 |
| 保留审计判断权 | AI 只生成线索与草稿，最终结论必须由审计人员确认 |

### 2.3 MVP 成功标准

MVP 被认为成功，需同时满足：

1. 能在 16GB 内存的 Windows 轻薄本上稳定运行。
2. 能批量导入原生 PDF 和扫描 PDF，损坏文件不阻塞整批任务。
3. 能配置至少两家文本模型和两家视觉模型，并在界面切换。
4. 能从风险结论跳转至对应文档页码和原文证据。
5. 金额及统计指标可以由本地代码独立复算。
6. 能对新增资料执行增量分析，并保留风险历史版本。
7. 能输出 Word、Excel、PDF 三种格式的审计工作成果。
8. 严格离线模式下无任何外部模型或 Embedding 请求。
9. 应用 CPU 持续平均不高于 35%，短时峰值不高于 45%。

## 3. 背景与问题

### 3.1 当前业务痛点

- 审计资料分散在多年报告、合同、凭证、纪要和银行资料中。
- 资料数量多，人工逐份查看耗时，跨年度对比困难。
- 扫描件无法直接全文搜索，表格和金额容易漏查。
- 通用聊天工具缺少风险状态、证据链、反证、版本和审计留痕。
- 将全部资料一次性发送给模型成本高、泄密风险大，且超过上下文限制。
- 模型生成的金额和统计结果可能不稳定，无法直接作为审计结论。
- 大型知识库平台依赖多项服务器服务，不适合轻薄本和单人场景。

### 3.2 产品解决思路

平台在本地建立项目证据仓，对所有资料进行可恢复的批量处理；再通过全文检索、向量检索和结构化查询，从完整资料范围中筛选最相关证据，仅将必要内容发送给外部模型。

模型输出不能直接成为最终审计结论。系统必须同时保存本地计算结果、触发规则、支持证据、反证、假设、不确定性和人工确认状态。

## 4. 用户与使用场景

### 4.1 目标用户

MVP 只面向单人内部审计人员，不建设组织架构、部门、多角色权限和审批流程。

用户具备以下特征：

- 熟悉财务报表、审计程序和风险判断。
- 能理解科目、年度、主体、金额和凭证等概念。
- 不要求具备大模型、向量数据库或编程知识。
- 需要对 AI 结果进行复核，而不是完全自动化审计。

### 4.2 核心场景

#### 场景 A：审前资料准备

用户建立项目并批量导入多年审计报告、年报、科目资料、凭证、合同、会议纪要和银行资料。平台完成哈希去重、文档分类、页级解析和索引。

#### 场景 B：跨年度风险评估

用户查看多年指标、异常余额、结构变化、重复事项和勾稽差异。系统形成风险卡片，并列出支持证据、反证和可能原因。

#### 场景 C：现场审计取证

用户从风险卡片跳转到原始文档页码，查看原文、记录备忘录、补充人工意见并调整风险状态。

#### 场景 D：访谈准备

平台依据已识别风险生成资料清单和访谈问题。用户可以修改、排序、删除和导出。

#### 场景 E：报告出稿

平台将已核实风险和引用证据写入固定模板。用户二次编辑后导出 Word、Excel 和 PDF。

#### 场景 F：严格离线使用

用户启用严格离线模式后，平台禁止全部外部请求，仅允许查看本地资料、搜索、计算和访问已有结果。

## 5. 产品原则

1. **本地优先**：原始资料和审计成果默认不离开本机。
2. **最小外发**：外部 API 仅接收完成任务所需的最小证据范围。
3. **计算确定性**：金额和统计指标必须由本地代码计算并可复算。
4. **证据优先**：任何风险结论必须能够回到来源文档和页码。
5. **人工确认**：模型不得直接写入最终审计结论。
6. **模型可替换**：服务商和模型变化不应要求升级应用代码。
7. **任务可恢复**：长任务必须支持暂停、重试、断点恢复和应用重启恢复。
8. **轻量运行**：默认配置以 16GB 轻薄本为基准，不依赖本地模型。
9. **结果可追溯**：保留规则版本、模型版本、输入范围、输出和人工变更记录。

## 6. 产品范围

### 6.1 MVP 必须完成（P0）

- 项目创建、打开、归档和年度范围设置。
- PDF 批量上传、增量上传、哈希去重和损坏文件跳过。
- 任务进度、暂停、继续、失败重试、跳过和断点恢复。
- 原生 PDF 本地文本抽取、页码、表格候选和可用坐标提取。
- 扫描页调用视觉模型 API，保存结构化结果和页码映射。
- 文档类型、年度、主体、科目、金额和风险类型抽取。
- 全文检索、向量检索和 DuckDB 结构化查询联合取证。
- 确定性财务规则、同比趋势、MAD 和结构占比分析。
- 风险卡片、风险状态、证据、反证、人工意见和历史版本。
- 资料清单、访谈问题、风险清单和管理层材料生成。
- Word、Excel、PDF 导出。
- 多模型配置、能力注册、任务路由、备用模型和调用记录。
- 本地 CPU/内存治理和严格离线模式。

### 6.2 MVP 建议完成（P1）

- API 用量和费用预估。
- 高风险事项第二模型复核。
- 项目回收站和可恢复删除。
- OCR 坐标可靠时的区域高亮。
- 可配置 Rerank API。
- 模型调用缓存管理界面。

### 6.3 MVP 明确不做

- 本地大模型、本地 Embedding 模型和 GPU 推理。
- 多用户、部门、角色、权限和审批体系。
- 全自动三张表深度勾稽和全自动责任界定。
- 领导任期自动拆分和复杂关系图谱。
- 实时流数据、移动端和复杂管理驾驶舱。
- 对所有扫描件承诺字符级坐标高亮。
- 将隐藏思维链或“完整推理过程”作为产品输出。
- 一次性将全部 11 年资料发送给大模型。

## 7. 信息架构

MVP 主界面由六个一级区域组成：

| 区域 | 主要内容 |
|---|---|
| 项目 | 项目列表、年度范围、处理概况、最近活动 |
| 资料 | 上传队列、文档列表、解析状态、PDF 阅读器 |
| 分析 | 多年指标、异常检测、检索和分析任务 |
| 风险 | 风险卡片、状态、证据、反证和人工意见 |
| 输出 | 资料清单、访谈问题、报告模板和导出历史 |
| 设置 | 模型服务商、任务路由、资源上限、隐私和离线模式 |

### 7.1 全局状态栏

所有页面顶部应始终显示：

- 当前项目名称。
- 当前是否允许外部 API。
- 正在运行的后台任务数量及进度。
- 当前主模型和视觉模型。
- CPU/内存保护是否正在限速或暂停任务。

## 8. 核心业务流程

### 8.1 项目初始化流程

1. 用户点击“新建项目”。
2. 输入项目名称、年度起止、被审计主体和本地存储位置。
3. 选择默认模型方案和是否允许外部 API。
4. 系统创建项目目录、SQLite 记录、DuckDB 分析库和索引版本。
5. 系统展示空项目工作区和资料上传入口。

### 8.2 文档导入流程

1. 用户选择单个或多个 PDF。
2. 系统计算 SHA-256 文件哈希。
3. 命中同项目已有哈希时，提示复用已有解析结果。
4. 系统判断文件是否损坏、是否存在可用文本层。
5. 原生 PDF 进入本地解析；扫描页进入视觉任务队列。
6. 页面解析结果按页落盘，生成全文索引和结构化数据。
7. 需要时调用 Embedding API 创建向量索引。
8. 任务完成后展示成功、跳过、失败和人工校正数量。

### 8.3 风险分析流程

1. 用户选择年度、主体、科目或分析模板。
2. 本地引擎运行确定性规则和统计指标。
3. 检索器在全部项目资料中召回相关证据。
4. 上下文构建器去重并限制证据数量。
5. 模型根据指标和证据生成风险解释、可能原因和补充程序建议。
6. 系统创建风险卡片，状态默认为“待复核”。
7. 用户查看证据并修改状态、等级和人工意见。
8. 系统保留原始模型结果和每次人工变更。

### 8.4 增量更新流程

1. 新资料完成解析后，系统提取受影响年度、主体、科目和风险类型。
2. 只重跑相关指标、检索和风险分析。
3. 新结论与旧结论形成版本差异。
4. 用户确认后，当前风险卡片更新，但旧版本不可覆盖删除。

### 8.5 报告导出流程

1. 用户选择已核实风险和报告模板。
2. 系统校验风险状态、证据完整性和必填字段。
3. 模型只接收已确认风险及必要证据，生成文字草稿。
4. 用户在界面完成二次编辑。
5. 系统导出 Word、Excel 或 PDF。
6. 导出物记录模板版本、生成时间、风险快照和模型来源。

## 9. 详细功能需求

### 9.1 项目工作区

#### PRD-PROJ-001 新建项目（P0）

**需求说明**

用户可以创建独立审计项目，每个项目拥有隔离的文件、数据库、模型配置和导出记录。

**必填字段**

- 项目名称。
- 年度起止范围。
- 被审计主体。
- 本地存储位置。
- 默认模型方案。

**验收条件**

- 项目名称重复时给出明确提示。
- 存储位置不可写时禁止创建。
- 创建成功后能够重新打开。
- 项目之间的文档、风险和日志不得混用。

#### PRD-PROJ-002 项目概览（P0）

概览页面展示：

- 文档数量、页数和处理状态。
- 待处理、运行中、失败和已完成任务数量。
- 待复核、高风险、已核实和已排除风险数量。
- 最近上传、最近分析和最近导出。
- 当前模型方案及外部 API 状态。
- 当前资源使用和后台限速状态。

#### PRD-PROJ-003 项目删除（P1）

- 删除前必须二次确认。
- 默认优先移入项目回收站。
- 删除范围应明确列出原始文件、索引、数据库和导出物。
- 删除行为写入本地审计日志。

---

### 9.2 文档上传与任务队列

#### PRD-UPL-001 批量上传（P0）

- 支持拖放和文件选择器。
- 单次可选择至少 500 个 PDF 或等量合成文件。
- 显示每个文件的文件名、大小、哈希、状态和处理进度。
- 损坏文件报错后整批继续。
- 支持暂停整批、继续、取消、重试失败项和跳过单项。

#### PRD-UPL-002 哈希去重（P0）

- 上传后计算 SHA-256。
- 同一项目中命中相同文件时默认复用结果。
- 用户可选择保留为新版本，但不得重复调用 API，除非明确要求重新解析。

#### PRD-UPL-003 任务恢复（P0）

- 每个处理步骤完成后写入安全点。
- 应用被关闭或异常退出后，任务状态不得丢失。
- 重新打开应用时，用户可继续或取消未完成任务。
- 已完成的步骤不得重复执行和重复计费。

#### PRD-UPL-004 失败处理（P0）

需要统一识别并展示：

- 文件损坏。
- 密码保护。
- API 超时。
- HTTP 429 限流。
- 余额不足。
- 无效 JSON。
- 服务不可用。
- 本地磁盘不足。
- 系统资源触发暂停。

每项错误必须提供可执行的下一步，如重试、切换备用模型、跳过或人工处理。

---

### 9.3 PDF 阅读与解析

#### PRD-DOC-001 PDF 阅读器（P0）

阅读器至少支持：

- 页码跳转。
- 缩放和适应宽度。
- 文本搜索。
- 原文复制。
- 风险证据定位。
- 备注和批注。
- 原生 PDF 文本高亮。
- 扫描件页级定位。

#### PRD-DOC-002 原生 PDF 解析（P0）

- 优先在本地提取文本，不发送整个文件给模型。
- 保存页面、文字块、块序号、原文、坐标、表格候选和解析版本。
- 表格抽取不可靠时保存原文页作为最终证据。

#### PRD-DOC-003 扫描 PDF 解析（P0）

- 扫描页按需逐页渲染，不把整份 PDF 常驻内存。
- 页面图像上传完成后立即释放内存和临时文件。
- 视觉模型必须输出固定 JSON 结构。
- 保存服务商、模型版本、页码、识别结果、置信信息和错误。
- 模型提供可靠坐标时允许区域高亮；否则只保证准确页码定位。

#### PRD-DOC-004 人工校正（P0）

用户可以校正：

- 文档类型。
- 年度。
- 被审计主体。
- 科目。
- 金额。
- OCR 原文。
- 风险类型。

人工校正必须保留修改前值、修改后值、时间和来源。

---

### 9.4 检索与证据构建

#### PRD-RET-001 全文检索（P0）

- 支持中文关键词、精确数字、文档名和页码搜索。
- 支持按年度、主体、科目和文档类型过滤。
- 搜索结果必须展示命中片段和来源页码。

#### PRD-RET-002 向量检索（P0）

- Embedding 通过外部 API 获取。
- 向量维度写入索引版本。
- 不同模型或不同维度的向量不得混用。
- 模型切换后允许新建索引，不覆盖旧索引。
- sqlite-vec 不兼容时回退到 FTS5 加内存余弦检索。

#### PRD-RET-003 混合取证（P0）

默认流程：

1. 识别问题中的年度、主体、科目和风险意图。
2. DuckDB 返回结构化指标和异常结果，默认不超过 200 行。
3. FTS5 召回关键词结果，默认不超过 50 块。
4. 向量检索召回语义结果，默认不超过 50 块。
5. 融合排序后保留 20～30 个证据块。
6. 按证据编号、文档名、页码和原文组合上下文。

#### PRD-RET-004 最小上下文（P0）

- 系统可以在全部 11 年资料中检索，但不得把全部资料发送给模型。
- 每次请求只发送当前问题相关的结构化指标和证据片段。
- 调用日志记录发送了哪些文档页码和证据编号。

---

### 9.5 异常识别与风险分析

#### PRD-RISK-001 确定性财务规则（P0）

至少覆盖：

- 借贷平衡。
- 合计一致性。
- 期初与期末衔接。
- 跨表勾稽。
- 重复金额或重复记录。
- 异常方向。
- 缺失年度或异常空值。

规则必须具有唯一编号和版本。

#### PRD-RISK-002 趋势与稳健统计（P0）

支持：

- 同比增减。
- 连续上升或下降。
- 趋势拐点。
- 中位数和 MAD。
- Z-score 辅助指标。
- 科目占资产、收入或费用的结构占比。

约束：

- 11 年样本较少，Z-score 不得单独决定高风险。
- 样本不足时必须提示不确定性。
- 分母、会计口径和缺失年度必须明确。

#### PRD-RISK-003 模型解释（P0）

模型接收本地指标和检索证据后，输出：

- 风险摘要。
- 触发原因。
- 支持证据。
- 可能反证。
- 潜在业务原因。
- 需要补充的资料。
- 建议访谈对象和问题。
- 不确定性说明。

模型不得重新计算金额，也不得直接确定责任归属。

#### PRD-RISK-004 风险卡片（P0）

每张风险卡片包含：

| 字段 | 说明 |
|---|---|
| 风险编号 | 项目内唯一 |
| 风险类型 | 预设类型或人工自定义 |
| 风险等级 | 高、中、低或待评估 |
| 状态 | 待复核、已核实、已排除、待补证、已关闭 |
| 摘要 | 简要描述 |
| 触发规则 | 规则编号及版本 |
| 输入值 | 本地计算使用的数据 |
| 基线值 | 历史或对照基线 |
| 计算结果 | 指标、差额或异常分数 |
| 模型解释 | 模型生成的解释文本 |
| 支持证据 | 文档、页码、片段 |
| 反证 | 可能推翻风险的证据 |
| 人工意见 | 审计人员记录 |
| 模型来源 | 服务商、模型、调用时间 |
| 版本 | 风险结论历史版本 |

#### PRD-RISK-005 风险状态流转（P0）

允许流转：

- 待复核 → 已核实。
- 待复核 → 已排除。
- 待复核 → 待补证。
- 待补证 → 待复核。
- 已核实 → 已关闭。
- 新证据加入后，已核实或已排除风险可产生新版本并重新进入待复核。

人工修改状态时必须填写备注；历史状态不得覆盖删除。

### 9.6 审计备忘录

#### PRD-NOTE-001 备忘录管理（P0）

- 同一项目支持多条备忘录。
- 支持标题、正文、标签、创建时间和修改时间。
- 可关联一个或多个风险及文档页码。
- 用户可控制备忘录是否允许模型读取。

- 关联风险。

- 状态。

#### PRD-INT-002 访谈问题（P0）

### 9.8 报告生成与导出

#### PRD-EXP-001 固定模板（P0）

MVP 至少提供：

- 风险清单模板。
- 资料清单模板。
- 访谈提纲模板。
- 管理层材料模板。
- 证据包索引模板。

#### PRD-EXP-002 AI 草稿（P0）

- 只使用已确认风险和必要证据。
- 自动附带证据编号。
- 生成内容必须允许人工二次编辑。
- 不输出隐藏思维链。

#### PRD-EXP-003 多格式导出（P0）

- Word：保留模板字段、标题层级、表格和证据编号。
- Excel：适合风险清单、资料清单和结构化明细。
- PDF：由最终编辑版本生成，用于归档或分发。
- 导出结果必须与当前风险状态一致。
- 历史导出不得被新结果静默覆盖。

### 9.9 多模型配置与路由

#### PRD-MDL-001 服务商配置（P0）

每个服务商配置包含：

- 显示名称。

- 默认请求头。

- 重试次数。
- 是否启用。

#### PRD-MDL-002 模型档案（P0）

每个模型记录：

- 服务商。
- 模型名称。
- 文本能力。
- 视觉能力。
- JSON Schema 能力。
- 工具调用能力。
- Embedding 能力。
- 文件上传能力。
- 上下文长度。
- 单次输出上限。
- 费用配置。

#### PRD-MDL-003 任务路由（P0）

| 任务 | 默认能力要求 | 路由规则 |
|---|---|---|
| 快速抽取 | 低延迟、结构化输出 | 优先低成本模型，失败后切换备用模型 |
| 视觉识别 | 图片输入、JSON 输出 | 文本模型不支持视觉时自动路由到视觉模型 |
| 风险解释 | 长上下文、稳定指令遵循 | 使用用户指定主模型，高风险可启用第二模型复核 |
| 报告生成 | 长文本、格式稳定 | 只发送已确认风险和必要证据 |

#### PRD-MDL-004 模型切换（P0）

- 用户可在界面新增、编辑、禁用模型。
- 更换模型不需要修改应用代码。

- 项目和任务。

- 文档页码和证据编号。
- 请求数据摘要。
- 输入、输出 Token。
- 费用估算。
- 缓存命中。
- 重试次数。
- 结果状态和错误。

日志不得保存 API Key，不默认保存完整敏感正文。

## 10. 任务状态机

| 状态 | 允许动作 | 说明 |
|---|---|---|
| queued | 开始、取消 | 等待单工作器 |
| running | 暂停、取消 | 正在执行可重入步骤 |
| pausing | 等待 | 当前安全点完成后暂停 |
| paused | 继续、取消 | 进度和中间结果已落盘 |
| retry_wait | 立即重试、跳过 | API 限流或临时错误 |
| failed | 重试、跳过、查看错误 | 自动重试耗尽或不可恢复 |
| completed | 查看结果、重新运行 | 输出已提交 |
| cancelled | 重新运行 | 保留日志并清理临时文件 |

任务必须满足幂等性：同一步骤重复执行时不能重复生成风险、重复计费或破坏已完成结果。

## 12. 非功能需求

### 12.1 目标设备

- Windows 10 或 Windows 11。
- 4 核 8 线程以上 CPU。
- 16GB 内存。
- SSD 可用空间 100GB 以上。
- 不要求独立显卡。

### 12.2 性能与资源限制

| 指标 | 目标 |
|---|---|
| 空闲 CPU | 启动稳定后均值低于 5% |
| 应用持续 CPU | 不高于 35% |
| 应用短时峰值 | 不高于 45% |
| 整机暂停阈值 | 整机 CPU 超过 50% 持续 10 秒 |
| 整机恢复阈值 | 整机 CPU 低于 30% 持续 10 秒 |
| 空闲内存 | 后端、索引和任务服务合计不高于 2.5GB |
| 常规任务内存 | 目标不高于 5GB |
| DuckDB 内存 | 默认上限 2GB |
| DuckDB 线程 | 逻辑核心 25%，最多 2 个 |
| 本地 CPU 任务并发 | 1 |
| 外部 API 并发 | 默认 2，可配置为 1～4 |
| 磁盘保护 | 剩余空间低于 10GB 时停止新导入 |

说明：应用不能控制用户电脑上其他软件的资源消耗，因此“低于轻薄本 50% 性能”以本应用进程上限和整机阈值保护共同实现。

### 12.3 可恢复性

- 所有长任务必须分步提交。
- 应用退出后任务、风险、笔记和人工状态保持完整。
- 重启后已完成步骤不重复。
- 临时文件在启动时检查并清理。
- SQLite 写入采用短事务和单工作器，避免并发写冲突。

### 12.4 易用性

- 面向非技术财务人员，不展示模型参数术语作为主流程。
- 错误提示说明原因和下一步操作。
- 默认配置可直接使用，复杂参数收纳在高级设置中。
- 外部 API 状态、实际模型和计费风险必须清晰可见。
- 风险结果必须优先展示证据，而不是只展示模型文字。

## 13. 安全与隐私

### 13.1 本地访问安全

- 本地服务只监听 `127.0.0.1`。
- 浏览器会话使用随机本地令牌。
- 默认禁止局域网设备访问。

### 13.2 密钥安全

- API Key 不得以明文写入 SQLite、日志或导出物。
- 使用 Windows DPAPI、系统凭据库或等效方式保存。
- 密钥输入框默认遮蔽，仅允许重新设置，不直接显示完整值。

### 13.3 外发控制

- 所有模型请求必须经过统一外发拦截器。
- 外发前展示或记录服务商、模型、任务和数据范围。
- 默认只发送证据片段，不发送无关文档。
- 远端文件任务完成后主动调用删除接口。
- 删除失败进入重试队列并提示用户。

### 13.4 审计日志

日志至少记录：

- 项目。
- 用户动作。
- 文档和页码。
- 模型服务商和实际模型。
- 外发时间和数据摘要。
- 规则版本。
- 人工状态变化。
- 导出和删除操作。

日志不记录 API Key，不默认记录完整敏感正文。

- 任何模型输出不得直接覆盖人工确认内容。

## 17. 埋点与产品指标

MVP 只记录本地产品指标，不默认上传遥测数据。

建议指标：

- 单项目文档数和总页数。
- 文档处理成功率、跳过率和失败率。
- 平均每页解析时间。
- API 请求次数、Token、费用和缓存命中率。
- 风险卡片数量及状态分布。
- 风险证据完整率。
- 从风险卡片跳转证据的次数。
- AI 草稿被人工修改的比例。
- 应用 CPU、内存峰值和资源暂停次数。
- 导出次数和格式分布。

所有指标保存在本地，用户可以清理。

## 22. 主要风险与应对

| 风险 | 影响 | 应对措施 |
|---|---|---|
| 视觉模型数字误识别 | 金额和表格不可靠 | 本地勾稽、第二模型复核、人工校正、保留来源页 |
| 供应商接口变化 | 模型调用失败 | 能力注册、适配器隔离、用户可修改 Base URL 和模型名 |
| 11 年样本较少 | 统计误报 | MAD、规则、趋势和审计判断组合，不让 Z-score 单独定级 |
| API 数据外发 | 涉密和合规风险 | 最小证据、外发日志、项目策略和严格离线模式 |
| SQLite 单写限制 | 批量任务竞争 | 单工作器、短事务和幂等步骤 |
| 轻薄本资源波动 | 影响日常办公 | 应用硬上限、整机阈值、空闲优先和任务暂停 |
| 模型输出不稳定 | 结构化数据不可用 | JSON Schema、修复、备用模型和人工处理 |
| 开源许可证限制 | 商业交付风险 | 依赖清单、许可证归档，GPL/AGPL/修改版项目只借鉴 |
