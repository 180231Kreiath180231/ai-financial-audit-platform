# ADR-0004：科目余额表 CSV 与首批确定性规则

- 状态：已接受
- 日期：2026-09-22
- 关联：PRD 风险分析流程、F08、AGENTS.md 第 7.2 与第 14 节

## 背景

CSV 是否进入正式输入、首批财务规则及风险分级口径原为待产品决策事项。用户已通过 Grill Me 明确确认本 ADR 的全部数据契约、计算口径、版本策略、风险边界和验收标准。本决策把 CSV 纳入当前 MVP 的正式结构化输入，但不改变 PDF 证据链的 P0 地位，也不授权 Excel、凭证、跨表勾稽、统计模型或固定报告。

## 数据契约

- 一个项目对应一个被审计主体；单个文件使用一种币种和一种期间粒度，金额单位固定为元。
- 固定必填列为：`年度、期间、科目编码、科目名称、期初借方、期初贷方、本期借方、本期贷方、期末借方、期末贷方、币种、是否末级`。
- 首版只接受 `是否末级=1` 的末级科目。科目编码始终按文本保存，保留前导零，只去除首尾空格。
- `期间` 只允许 `01` 至 `12` 或 `FY`；月度与年度不得在一个数据集中混用。年度与期间、科目编码构成唯一键。
- 支持 UTF-8、UTF-8 BOM 和 GB18030 的英文逗号 CSV。额外列原样保存但不参与计算。单文件最大 100 MB、50 万行。
- 金额使用 `Decimal`，最多两位小数，空白金额按零计算并保留原始空白记录。负数、混合币种、非法金额、重复主键、非末级科目和结构错误均整批拒绝。

## 规则与风险

- 规则集版本为 `TB-RULESET-v1`，规则版本均为 `v1`。
- 结构与唯一性检查在导入边界执行。业务规则包括期初借贷平衡、本期发生额借贷平衡、期末借贷平衡、单科目余额公式和相邻期间衔接。
- 余额公式为：`期末借方-期末贷方 = 期初借方-期初贷方+本期借方-本期贷方`。金额比较容差为 `0.01`。
- 跨期按净额比较。新增科目期初为零视为通过；新增科目期初非零、科目消失但前期期末非零或相邻期不衔接视为失败。缺失完整期间时不跨期计算，结果为“无法计算”，不得显示为通过。
- 结果只有“通过、失败、无法计算”。规则失败按数据集、规则和期间聚合为“待评估”风险草稿，不自动判定高、中、低等级。
- 每个结果保存规则版本、输入值、基线、计算结果、原文件 SHA-256、数据集版本和 CSV 行范围。明细可分页回到参与计算或异常的原始行。

## 存储与生命周期

- SQLite 保存数据集、预览、任务、规则运行、风险与审计元数据；DuckDB 保存科目明细和规则结果。DuckDB 使用 2 GB 内存上限和最多 2 个线程。
- 导入使用“选择文件、结构校验与预览、用户确认、后台原子入库、自动运行规则”的流程。单工作器负责导入与计算。
- 数据集不可变，并在项目内按 SHA-256 去重。同一数据集与同一规则版本重复运行时复用已有结果，不创建重复风险。
- 规则口径变化必须提升版本，新结果不得覆盖旧结果。新数据通过也不自动关闭旧风险。
- 不提供硬删除，只允许归档。归档保留原文件、DuckDB 明细、规则结果、风险草稿和版本历史。
- CSV 和金额不发送给模型或外部服务。Fake Provider 只能解释已经由本地规则计算的结果。

## 依赖选择

采用 DuckDB Python 客户端作为嵌入式分析存储。它符合既有目标架构，不需要独立服务；相较继续把多年明细和分析查询放入 SQLite，能保持元数据事务与分析负载边界。锁定版本由 `uv.lock` 管理，许可证为 MIT，并提供 Python 3.12 的 Windows wheel。

## 明确不做

本迭代不实现 XLS/XLSX、凭证数据、财务报表勾稽、异常方向判断、MAD、Z-score、自动风险分级、PDF 表格取数、合并报表、税务规则、固定报告或新增导出格式。
