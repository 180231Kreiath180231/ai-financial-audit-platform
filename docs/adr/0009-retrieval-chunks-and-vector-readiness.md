# ADR-0009：可追溯检索分块与向量索引就绪边界

- 状态：已接受
- 日期：2026-09-22
- 关联：PRD-RET-001、PRD-RET-002、PRD-RET-003、F06、F07

## 背景

项目已有页级 FTS5 检索和结构化筛选，但向量检索需要稳定、可回溯的文本块，并且必须记录实际模型、维度和索引版本。允许使用的 Embedding 服务商及真实资料外发政策仍未获批准，因此本轮只能建设不触发外发的本地基础能力。

## 决策

- 项目迁移 v8 新增 `retrieval_chunks`，以确定性的字符窗口对非空页级原文分块。每块保存文档、页码、块号、字符起止位置、精确原文、SHA-256、解析方式、解析版本和分块版本。
- 既有页面在迁移时回填分块；新 PDF 导入在页面写入的同一事务中生成分块。空白页不生成伪内容。
- 新增 `vector_index_versions` 与 `chunk_embeddings` 存储契约。每个索引版本独立记录模型档案、实际模型、维度、分块版本、后端和状态；复合外键在数据库层阻止不同维度进入同一索引版本。
- 页面分块改变时，任何已就绪的向量索引会标记为 `stale`，避免继续把旧向量呈现为可用结果。
- 定义本地 Reciprocal Rank Fusion 纯函数，用于后续合并关键词与向量排名，不比较不可兼容的原始分数。
- 状态 API 和前端明确区分全文分块、语义索引状态及是否发生外部请求。当前语义检索显示为“待配置”，而不是伪装为可用。

## 安全与实现边界

- 本轮不选择 Embedding 服务商，不发起 Embedding、Rerank 或其他外部请求，不读取或复用聊天中出现的明文密钥。
- 本轮不新增 sqlite-vec 或其他第三方依赖。后续在 Windows 上验证 sqlite-vec；验证失败时按 PRD 回退到内存余弦检索。
- 本轮尚未把向量召回接入搜索 API，因而不宣称 PRD-RET-002 或 PRD-RET-003 已完成。
- 真实向量构建必须先确认服务商与数据政策，并继续满足严格离线关闭、项目允许外发、统一网关审计和最小必要文本原则。

## 结果

项目现在具备可迁移、可复核、可判定失效的检索分块与向量版本数据契约。后续 Embedding 接入可以复用这套边界，而无需重写页级证据来源或混用不同维度。
