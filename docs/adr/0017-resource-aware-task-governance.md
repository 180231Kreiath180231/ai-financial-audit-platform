# ADR-0017：整机资源感知的任务治理

- 状态：已接受
- 日期：2026-09-23
- 关联：PRD-UPL-003、P03、P04

## 背景

本地单工作器原先只上报 CPU 和内存快照，不会依据整机压力改变任务调度。持续高 CPU 时后台处理可能影响用户查看与复核；内存超过安全线时继续启动新任务也会扩大压力。任务已有安全点暂停能力，但没有区分用户主动暂停和系统资源暂停，自动恢复存在误恢复用户任务的风险。

## 决策

1. 工作器以 1 秒间隔读取整机 CPU 和内存。CPU 严格超过 50% 持续 10 秒后，请求运行任务在下一个安全点暂停；CPU 严格低于 30% 持续 10 秒后，恢复由资源保护暂停的任务。
2. 内存严格超过 70% 时立即关闭新任务准入；已经运行的任务不因内存阈值被强制中断。排队任务显示“系统内存使用超过 70%，等待资源释放”，回落到 70% 或以下后恢复准入。
3. CPU 保护生效期间也不领取新的排队任务。运行任务只在既有安全点停下，不终止线程、不打断数据库提交，也不删除输入文件。
4. 项目数据库迁移 v15 增加 `tasks.pause_reason`，只允许 `user` 或 `resource`。自动恢复只处理 `resource`；用户暂停必须由用户继续。
5. 若 CPU 在任务到达安全点前已经恢复，则将资源 `pausing` 状态改回 `running`；已经安全暂停的资源任务改回 `queued`。应用重启时资源暂停任务重新排队并重新评估整机状态，用户暂停保持不变。
6. 阈值状态机与系统采样、数据库动作分离。测试可注入采样值和单调时钟，验证持续窗口、尖峰复位和严格边界，不依赖测试机器的即时负载。
7. 所有自动暂停请求、暂停落点、自动恢复、内存阻塞和内存恢复均写入项目审计事件。前端对资源暂停使用只读状态说明，不显示手动“继续处理”，但仍允许取消已暂停任务。

## 影响

- 资源治理与任务处理并行运行，因此长任务执行期间仍能持续观察整机压力。
- CPU 短时尖峰不会暂停任务；连续窗口中任一不满足阈值的采样都会重新计时。
- 内存门禁控制新任务准入，不承诺降低当前进程已经占用的内存。
- 自动化验证覆盖确定性状态变化；P03/P04 的正式发布门禁仍需在目标 Windows 设备上制造真实负载，核对采样时序、交互响应和审计记录。
