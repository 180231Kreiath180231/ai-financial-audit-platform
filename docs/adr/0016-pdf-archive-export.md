# ADR-0016：PDF 审计工作成果归档件

- 状态：已接受
- 日期：2026-09-23
- 关联：PRD-EXP-003、F11、ADR-0012、ADR-0014

## 背景

Excel 风险清单与 Word 工作成果包已经能够从同一最终固化草稿生成。按照 ADR-0012 已确认的格式顺序，下一切片需要生成适合归档和分发的 PDF，同时保持内容来源、版本和导出历史一致。

## 决策

1. PDF 直接读取不可变快照和最终固化草稿，不从 Word 文件提取或转换业务内容。
2. 使用 ReportLab 和版本化配置 `templates/audit-work-products-pdf-v1.json` 在本地生成 A4 归档件，不调用模型或外部服务。
3. PDF 包含项目及固化元数据、风险清单、锁定证据索引、资料清单和访谈提纲；语义内容与 Word 使用同一草稿版本，版式无需像素级相同。
4. 使用 Windows 自带 Microsoft YaHei，缺失时回退到 SimSun/SimHei，并把实际中文字形子集嵌入文件；找不到可嵌入中文字体时拒绝生成并返回可操作错误。
5. 生成后用 pypdf 重新打开并确认至少包含一页，再计算 SHA-256、原子移动到项目导出目录并写入导出记录。
6. 项目数据库迁移 v14 将 `output_exports.export_format` 扩展为 `xlsx`、`docx` 或 `pdf`，保留既有 Excel 和 Word 记录及复合外键。
7. 每次生成使用新的导出编号和路径；文件名包含日期、草稿版本和导出编号片段，历史文件不覆盖。

## 影响

- Word、Excel 和 PDF 共享同一内容版本和审计轨迹，F11 三格式基础链路具备实现条件。
- 新增 ReportLab BSD-3-Clause 生产依赖；发布时仍需归档其完整许可证和传递依赖清单。
- Windows 中文字体不随应用重新分发，避免引入字体许可证；目标运行环境继续限定为 Windows 10/11。
- PDF 归档件是只读交付格式，内容修改必须回到源快照创建新草稿并重新固化。
