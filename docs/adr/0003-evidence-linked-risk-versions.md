# ADR-0003：证据关联风险卡与不可覆盖版本

- 状态：已接受
- 日期：2026-09-22
- 关联：PRD-RET-001 至 004、PRD-RISK-003 至 005、F06、F09、F10

## 决策

- 第一阶段只允许人工从本地文档搜索命中中选择支持证据或反证。风险等级固定为“待评估”，触发规则固定为 `MANUAL-DRAFT / v1`，不伪造尚未确认的财务规则、金额复算或责任判断。
- 浏览器提交项目内文档、页码、文本块、命中片段和证据方向；服务端必须重新读取项目 SQLite 中的原文并验证片段完全匹配。不存在、被篡改或同时标为两个方向的片段拒绝入库。
- 风险证据固化文档名、页码、文本块、引用原文、解析方式和解析版本。风险台账可从固化证据回跳到 PDF 页码并重新搜索原文。
- 状态流转严格限制为：待复核→已核实/已排除/待补证，待补证→待复核，已核实→已关闭。每次流转必须包含人工备注。
- 创建、状态流转和 Fake Provider 合成解释都会增加风险版本并保存完整快照；历史版本不可覆盖。
- 合成解释只允许本地 Fake Provider，输出必须包含不确定性声明，不得计算金额或生成审计结论。模型调用只保存请求摘要和证据引用，不保存提示词原文。
- 服务启动时自动迁移所有可用的既有项目数据库。单个项目迁移失败时，该项目显示为存储不可用，不影响其他项目进入工作台。

## 结果

该设计先建立“搜索命中→证据固化→风险草稿→人工复核→版本历史”的可审计链路，同时保持规则和模型能力边界诚实。后续确定性规则可写入现有输入值、基线、计算结果和规则版本字段，而无需改变证据与版本模型。

F06 的 PDF 页码与原文片段回溯、F09 的基础状态流转已经覆盖。F10 的新证据追加、目标风险显式重开、旧版本保留和相邻版本差异已由 [ADR-0020](0020-incremental-risk-reassessment.md) 补齐。
