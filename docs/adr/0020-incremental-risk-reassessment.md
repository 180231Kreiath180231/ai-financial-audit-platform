# ADR-0020：新证据增量回溯与风险显式重开

- 状态：已接受
- 日期：2026-09-23
- 关联：PRD-RISK-005、F08、F10

## 背景

风险卡已经保存不可覆盖版本，但既有风险确认后不能追加新证据，也不能展示相邻版本的具体变化。F10 要求加入可能推翻旧风险的新证据时，只重新评估相关风险并保留旧版本。

## 决策

1. 新证据必须由用户从当前项目原文中选择，并在目标风险上明确执行“关联证据并重新评估”；系统不根据支持或反证方向自动推断审计结论。
2. 服务端重新验证文档、页码、文本块和引用原文。已关联证据、相反方向重复关联、篡改原文和跨项目证据均失败关闭。
3. 每次操作只影响用户选择的一张风险卡。当前状态统一进入“待复核”，风险等级不自动改变；其他风险不增加版本。
4. 新证据追加到当前证据集合，不删除旧证据。旧风险快照和历史导出保持不可变。
5. 依赖旧证据范围的当前模型解释、服务商和调用标识失效并清空；旧解释仍保存在历史版本中，重新生成仍需经过待复核门禁。
6. 每次增量回溯在同一 SQLite 事务中追加证据、更新当前风险、创建完整快照并写入 `risk.evidence_reassessed` 审计事件。事件只记录证据标识和影响范围，不复制敏感原文。
7. 文档证据变化不修改不可变财务数据集，也不伪造金额重算。确定性规则输入、基准和结果继续保留在新快照中；未来若支持替换财务数据集，应按规则结果依赖关系另建增量计算任务。
8. 风险详情按相邻版本显示状态、等级、人工意见、证据增减、模型解释和规则数据差异；颜色不作为唯一变化提示。

## 影响

- 复用现有 `risk_evidence` 与 `risk_versions`，不需要数据库迁移。
- 已固化输出继续引用原风险版本；风险重开后不会回写或覆盖既有 Excel、Word、PDF。
- F10 的当前 MVP 边界是项目内新文档证据触发单风险重新评估，不包含自动责任判断或模型自动改写人工结论。
