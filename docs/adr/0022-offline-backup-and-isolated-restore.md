# ADR-0022：离线完整备份与隔离恢复

- 状态：已接受
- 日期：2026-09-24

## 背景

详细 PRD 把安装、升级、备份、恢复和卸载实机演练列为发布条件。仓库此前具备 SQLite 自动迁移和项目级数据目录，但没有能够完整收集注册库、密钥密文、内外部项目目录并验证恢复结果的运维入口。

安装器技术尚未在产品资料中确定。选择 MSIX、MSI 或 Inno Setup 会改变部署和升级方式，属于 `AGENTS.md` 要求先决策的范围。因此本 ADR 只确定与安装器无关、可逆的本地数据备份和恢复协议，不代替安装、升级或卸载决策。

## 决策

1. 使用目录格式 `hengjian-local-backup-v1`，不额外引入压缩、加密或云端依赖。
2. 备份和恢复都要求操作者先停止应用，并显式传入 `--confirm-app-stopped`；工具不尝试在线热备份。
3. 备份包括：
   - 应用注册库 `registry.db`；
   - `secrets/` 中的 Windows DPAPI 密文；
   - 注册库中全部项目的 `app.db`、原始文件、派生文件、隔离件、导出物和临时状态；
   - 位于应用数据目录之外的项目，以及位于应用数据目录之内的项目。
4. SQLite 数据库使用 SQLite Backup API 生成一致快照，不直接复制活动中的 WAL；项目若位于应用数据目录内，只在 `projects/<project-id>/` 保存一次，避免重复。
5. 清单记录每个文件的相对路径、字节数和 SHA-256。恢复前必须完成文件清单、哈希和所有 SQLite 数据库的 `integrity_check`。
6. 备份拒绝符号链接、路径穿越、重叠项目目录和位于源目录内的输出位置。
7. 恢复只允许写入尚不存在的应用目录和项目目录，不覆盖当前数据。恢复后把注册库中的项目路径统一改写为新项目根目录下的稳定项目编号路径。
8. 备份和恢复先写入同父目录暂存区，再发布最终目录；Windows 短时扫描句柄导致的改名冲突只做有限重试。
9. 备份是完整敏感数据副本，必须由操作者放在访问受控的位置。工具不把“目录格式”包装成已加密归档。
10. DPAPI 密文只能由原 Windows 用户和系统上下文解密。同用户、同设备恢复需要通过真实 DPAPI 解密检查；跨用户或跨设备恢复后必须重新录入外部服务密钥。
11. SHA-256 清单用于发现清单保留前提下的意外损坏或文件变化，不提供签名或对抗具有备份写权限攻击者的真实性证明。

## 影响

- 本地数据可以在不依赖 OCR、模型 API 或网络的情况下完整验证并恢复到隔离位置。
- 备份不会修改源注册库、项目路径、项目文件或历史导出。
- 恢复不会覆盖现有目录，因此切换到恢复副本需要操作者显式设置 `AUDIT_DATA_DIR` 后重新启动应用。
- 目录备份本身没有密码或整体加密；若产品需要可移植加密包，必须先完成“本地数据库整体加密”待决策项。
- 安装器、程序文件升级、卸载时的数据保留策略和跨设备密钥迁移仍未决定，本 ADR 不宣称这些发布门禁已经通过。

## 验证

- 自动化覆盖应用内嵌项目、外部项目、注册库、项目数据库、普通文件、DPAPI 密文文件、哈希篡改、显式停止确认和禁止覆盖。
- Windows 合成实机演练额外验证真实 DPAPI 加密/解密、审计事件数量、严格离线状态、项目路径改写和恢复后数据库启动。
- 演练全程使用合成数据，外部请求为 0。
