# ADR-0001：MVP 生产工程基线

- 状态：已接受
- 日期：2026-09-22
- 关联：PRD-PROJ-001、PRD-PROJ-002、PRD-UPL-001 至 004、PRD-DOC-001 至 002、F01、F02、F03、F06

## 决策

- 使用 `frontend/` React + TypeScript + Vite 和 `backend/` FastAPI 工程。
- 依赖分别由 npm 和 uv 管理，版本固定在锁文件中。最初方案中的 pnpm 在当前 Windows 环境缺少可执行模块，采用系统现有 npm 以保证安装与启动可复现；此变化不影响前后端边界或产物格式。
- 后端只监听 `127.0.0.1`；浏览器通过随机 HttpOnly Cookie 建立本机会话。
- 全局 registry SQLite 只保存项目入口；每个项目在独立目录保存自己的 `app.db`、原始 PDF、处理中间文件、隔离文件与导出目录。
- 第一版使用一个持久化本地工作器。导入步骤为落盘、SHA-256、PDF 完整性检查、页级文本提取和结果提交；重启时把 `running` 恢复为 `queued`，把 `pausing` 固化为 `paused`。
- 前端使用 PDF.js 按需加载阅读器。原型 V3.2 保持只读，生产界面通过组件和真实 API 状态重建。
- 默认 synthetic 演示项目和严格离线；不连接真实模型、OCR、Embedding 或遥测端点。

## 暂不包含

- 扫描 PDF 的视觉识别、字符级坐标和人工 OCR 校正。
- DuckDB、财务规则、风险等级和模型解释。
- Word、Excel、PDF 报告模板与导出。
- SQLite 加密和项目级密码。

这些能力分别依赖仓库待产品决策登记，不在本 ADR 中假设或提前实现。

## 结果

该基线提供一个可启动、可测试、可恢复的文档纵向切片。后续迭代必须复用同一项目隔离、任务状态、会话安全和错误码约定，不得从前端直连外部模型。
