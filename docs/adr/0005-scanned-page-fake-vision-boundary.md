# ADR-0005：扫描页检测与 Fake Vision 安全边界

- 状态：已接受
- 日期：2026-09-22
- 关联：PRD-DOC-003、PRD-DOC-004、F05、F07、PRD-OFF-001

## 背景

原生 PDF 已具备本地文本抽取与页码证据，但无足够文本层的扫描页此前会被当作空白页提交。真实页面是否允许上传、是否要求本地预脱敏、允许使用哪些视觉服务商仍需业务和数据政策确认，因此本增量不能默认开启真实 OCR 外发。

## 决策

- pypdf 抽取后，页面非空白字符少于 12 个时标记为扫描页候选。
- 页面只在需要时使用 pypdfium2 按 1.5 倍比例逐页本地栅格化；每次只保留一个临时 PNG，处理完成、失败、暂停或取消后都立即释放并删除。
- 自动 Fake Vision 仅允许用于标记为 synthetic 的项目。Fake Provider 只接收页面编号、图像尺寸和 SHA-256，不接收图像字节；结果明确标记为 synthetic，不生成真实业务文字或审计结论。
- 非 synthetic 项目只保存 `requires_vision`，不渲染、不调用模型、不上传页面。严格离线策略不会被该流程绕过。
- 页级结果使用 `vision-page.v1` 固定 JSON，保存状态、服务商、实际模型、调用编号、图像摘要、置信信息、解析版本、错误和外部请求标记。
- Fake Vision 识别文本进入既有页级全文检索，因此可以验证“搜索命中 → 页码定位 → 证据固化”链路；界面始终显示这是合成结果以及外部请求为 0 次。
- 文档级解析方法区分 `native_pdf`、`fake_vision`、`hybrid_pdf` 和 `scan_detected`；历史文档无需重写。

## 依赖与许可

- pypdfium2 5.13.0：Apache-2.0 OR BSD-3-Clause；其 PDFium 二进制为 BSD-style 许可证。
- Pillow 12.3.0：HPND。
- 两项依赖均提供 Windows 可用发行物，不引入 GPL/AGPL、GPU、Docker或独立服务。

## 后果

该切片验证扫描页识别、内存与临时文件生命周期、固定输出、模型审计和准确页码定位，但不代表真实 OCR 质量或 F07 已完整验收。接入真实视觉模型前仍需确认整页上传/预脱敏政策、允许的服务商、数据保留条款和 synthetic 兼容测试账号。
